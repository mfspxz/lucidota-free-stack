## 2. Compartmentation rules
Zackary's rule: **no provider EVER gets the full picture.**

### What NEVER leaves his server
API keys and Infisical root. SSH/private keys. Customer PII. The complete n8n workflow graph (no single provider sees all workflows). Wallet/credential material. The full business plan. Anything that would let one provider reconstruct the operation.

### Fragmentation rules
- **Prompts:** no single AI lane receives more than ~1/3 of any sensitive document's context in one request. Chunk and distribute across lanes.
- **Code:** public-safe code on GitHub; sensitive modules (billing logic, key handling, proprietary algorithms) self-host only.
- **Data:** PII stays on server + Neon. Managed analytics lanes (PostHog, Cloudflare) get aggregates only.
- **FOE lanes** (NVIDIA NIM, Kilo gateway, xAI): public-fragment tasks only — research summaries, public code, content drafts. Never credentials, never strategy, never PII.

### Key storage
Infisical self-hosted on his server = sole source of truth. Doppler free = encrypted offsite backup. Local encrypted export on server = third copy. Rotation: on any provider breach suspicion, rotate that provider's keys within 1 hour; full rotation quarterly.

### "No provider gets the full picture" — enforcement checklist
- [ ] No AI lane receives >1/3 of any sensitive context in a single request.
- [ ] FOE providers receive public fragments only (spot-check prompts monthly).
- [ ] Secrets exist in exactly three places: Infisical self-host, Doppler encrypted backup, local encrypted export.
- [ ] Repos contain zero secrets — pre-commit scan enforced via GitHub Actions on every push.
- [ ] Every n8n workflow documents which providers it touches; no workflow mixes FOE lanes with sensitive data.
- [ ] On first import of `content-pipeline.json`: create the n8n **Header Auth** credential (any name) and attach it to the webhook trigger node — the workflow ships with a placeholder credential and must not be activated until a real one is attached (security fix 2026-10-05).
- [ ] One provider ToS re-verified per week on rotation (2026 die-off list: Brave, Storj, Render, Oracle ARM, MailerLite, Piwik PRO — free tiers die; catch it early).
- [ ] DNS stays parallel-authoritative across all four providers — verified quarterly via dig.
- [ ] Every new provider gets a trust classification (FRIEND/NEUTRAL/FOE) before first use. No exceptions.
- [ ] Kill-switch drill quarterly: pick one primary, simulate its death, confirm secondary takes over.

## 4. Kill-switch / death scenarios per layer
Format: primary dies → who takes over → how long → notes.

| Layer | Primary dies → takeover | Time | Notes |
|---|---|---|---|
| AI inference (bulk) | Google AI Studio 429/quota → router auto-rotates to Mistral → NVIDIA NIM | Seconds | Router-level, no human needed; alert fires to Kuma |
| AI inference (sensitive) | OVHcloud down → Groq → self-host | Seconds–minutes | Never fails over to a training lane |
| His server (total loss) | Cloudflare Workers (stateless) + Deno Deploy take web traffic; Inngest takes critical workflows | 15–60 min | Requires Deno Deploy standby pre-deployed in hour 20–22 (Koyeb needs a card and sleeps — demoted, not in the no-card path) |
| n8n specifically | Dies → cron-job.org heartbeat pages Lucidota within 5 min → Inngest runs critical workflows; Activepieces CE spun up from backup | 30–60 min | Dead-man's switch is the whole point of the external heartbeat |
| Database (Neon) | Dies → Aiven Free (restore nightly pg_dump) → D1 | 1–4 h | Restore time dominates; nightly dumps to B2 + Tigris are non-negotiable |
| DNS | Any one of four dies → other three still authoritative | Zero | Parallel, not failover — this is the design working as intended |
| CDN | Cloudflare dies → Gcore → origin-direct via R2/B2 | Minutes | DNS switch; origins on R2/B2 stay up |
| Object storage | R2 dies → B2 → Tigris | Minutes | Origin URL switch in Cloudflare Worker |
| Queue | Cloudflare Queues dies → QStash → Upstash Redis streams | Minutes | DLQ preserved on QStash |
| Scheduler | n8n cron dies → QStash → cron-job.org → Cloudflare cron | Minutes | Four-deep by design |
| Monitoring | Kuma dies → Upptime (external, GitHub Actions) → Better Stack | Minutes | Upptime lives outside his infra — that's why it's the secondary |
| Auth | Authentik dies → Logto managed → Authelia (internal) | 30–60 min | Logto config kept warm with synced user base |
| Secrets | Infisical dies → Doppler cloud backup → local encrypted export | Minutes | Three copies exist precisely for this |
| Email | Brevo dies → Sender → Kit | 30 min | Weekly list exports to MEGA vault; sender domain pre-verified on all three |
| Social | Buffer dies → Publer → Metricool | 15 min | Queue mirrored across Buffer + Publer continuously |
| GPU training | Kaggle quota exhausted → Colab → Beam (verify) | Hours | Weekly cadence absorbs this; not a real-time layer |
| Whole provider death (e.g., Cloudflare outage) | Gcore + deSEC DNS; compute on Deno Deploy; queues on QStash | 1–2 h | Pre-built runbook above; drill quarterly |
| 2026-style tier death (provider kills free tier) | Secondary already warm → swap within 24 h | ≤24 h | Weekly ToS re-verification rotation is the early-warning system |

### Master kill-switch (FOE provider compromise / suspected training on sensitive data)
1. Revoke that provider's API tokens immediately (Infisical → provider dashboard).
2. Rotate all keys that provider ever saw (1-hour rule).
3. Switch the lane to its secondary; update the Cloudflare router config.
4. Audit: pull logs, determine exactly what was sent, classify exposure.
5. Re-classify or delist the provider; update this runbook.
