# FreeStack Key Acquisition Runbook
Date: 2026-10-05. Frictionless checklist — Zackary signs up, hands keys to Lucidota via vault, Lucidota wires them in.
Standing rule: **$0. No card. No incorporation.** If ANY signup asks for a credit card → STOP that lane immediately, note which service asked, tell Lucidota, move to the next key. Never enter a card.

## Phase 0 — Before any key (Lucidota does this)

### 6b. ROUTER_KEY + AI_ROUTER_KEY (operator-generated — no signup)
The failover router is **fail-closed** (security fix 2026-10-05): it rejects every request without a bearer token, and returns 503 on every route if the secret was never set. These are generated by Lucidota during wiring — nothing for you to sign up for.

- **One value, three homes.** Lucidota generates a single token (`openssl rand -hex 32`) and provisions it as:
  1. `ROUTER_KEY` on the Worker itself: `wrangler secret put ROUTER_KEY`
  2. `AI_ROUTER_KEY` as a GitHub repo secret: `gh secret set AI_ROUTER_KEY --repo <ops-repo>` (the 3 Actions workflows read it as `secrets.AI_ROUTER_KEY`)
  3. `FREESTACK_ROUTER_KEY` in n8n's environment — **must be the same value** (see `server/DEPLOY.md` for the compose wiring)
- Wrong token → 401. Missing `ROUTER_KEY` on the Worker → 503 everywhere. This is what stops strangers from burning your free-tier quotas (Gemini 1.5K/day, Groq 14.4K/day, Mistral 1B/mo, NVIDIA 10K/day).
- Time: ~2 min, done by Lucidota in the Phase 1 wiring pass.

## Vault handoff — how keys get to Lucidota
1. You finish a signup. In chat you say: **"Key ready: Groq"** (name only — NEVER paste the key in chat).
2. Lucidota generates a **Secure Vault capture page** and gives you the link.
3. You open it and paste the key there. The vault returns Lucidota a reference — he never sees the raw value in chat, logs, or memory.
4. Repeat per key, in phase order. Batch them: do all of Phase 1, hand them over, then Phase 2, then Phase 3, then Phase 4.

### What Lucidota does with each key (so you know it's real work, not a drawer)
- **AI keys (Google, Groq, Mistral, z.ai, NVIDIA, OpenRouter)** → stored in Infisical; injected into the Cloudflare failover router via `wrangler secret put`; added as n8n credential nodes for workflow use. Router order: Google → Groq → Mistral → z.ai (optional) → NVIDIA NIM → OpenRouter; sensitive lane stays OVHcloud → Groq (keyless/anonymous, no signup needed).
- **Cloudflare API token** → used for `wrangler` deploys from the server; stored in Infisical; never in repos.
- **GitHub PAT** → `gh auth login` on the server; repo secrets set via `gh secret set` for Actions (Upptime, secret-scan, batch jobs).
- **Neon connection string** → Infisical; n8n Postgres credentials; app env on server. First `pg_dump` → B2 scheduled immediately.
- **Axiom token** → OpenTelemetry/Grafana config; n8n HTTP nodes for log shipping.
- **WeatherAPI key** → n8n/Worker env for scheduled weather pulls (paired with MET Norway, which is keyless).
- **Tavily + Exa keys** → Infisical; n8n HTTP nodes for the nightly research digest and ad-hoc research. Search failover order: Tavily → Exa → SearXNG self-hosted (keyless).
- **QStash token** → external cron schedules calling n8n webhooks from outside the server; DLQ monitored via the heartbeat workflow.
- **Upstash Redis URL/token** → ai-router upgrade path (per-lane RPM in Redis instead of in-memory = exact cross-isolate counts); n8n shared lock state. Budget cap verified at signup.

### Compartmentation reminder (your rule)
Keys exist in exactly three places: **Infisical self-host → Doppler encrypted backup → local encrypted export.** Never in chat. Never in repos (pre-commit secret scan runs on every push). Never inside AI prompts. On any breach suspicion: rotate that provider's key within 1 hour.
