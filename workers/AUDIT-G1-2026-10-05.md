**Method:** industry best-practice research → HN/arXiv/Reddit sweep → brutal critique → implement → dogfood live → 25/25 tests green.
**Verdict:** the old router was a competent prototype with production-killing gaps. It is now genuinely resilient. Single file, zero new dependencies.

## 1. Research: how the real world does failover

### Industry patterns (Envoy / Kong / Cloudflare AI Gateway / gRPC)
- **One logical deadline per request.** Every attempt gets `min(attempt timeout, time remaining)`; nothing outlives the deadline. Waiting is treated as a cost (Google SRE workbook, gRPC deadline guidance).
- **Retry budgets, not retry counts.** Envoy caps retries at 20% of active requests, Istio `retryBudget` ~10%, gRPC 10:1. A per-request "3 retries" triples load in a broad failure; a budget cannot, by construction. (sysdesign-academy retry-storm analysis; Bits to Billions Ep.21)
- **Retries live INSIDE the circuit breaker.** Retrying against an open breaker is not persistence, it's load. (Resilience4j guidance; Talkdesk postmortem: breakers cut a 20-min recovery to ~2 min.)
- **Per-route breakers with escalation, not one global breaker.** Envoy outlier detection ejects hosts after consecutive 5xx; a failing route must not block a healthy independent one.
- **Honor Retry-After, but cap it against the deadline.** Fail over instead when the asked wait exceeds what the request can afford. (free-llm-gateway, llm-gateway architecture docs)
- **Hedged requests for tail latency.** Google "Tail at Scale": fire a duplicate after ~p95 delay, take the first answer, cancel the loser. ~5% extra load for dramatic p99.9 improvement. Rules: idempotent ops only, budget-capped, disabled under overload. (gRPC `hedgingPolicy`; Istio hedging writeup; arXiv 2608.25403 on adaptive retry budgeting)
- **Exact-match caching.** Cloudflare AI Gateway and free-llm-gateway both cache identical prompts (SHA-256 of the request) — absorbs duplicate/canary traffic for free.
- **Dynamic penalty routing.** Providers that 429 sink in priority; penalties decay. (free-llm-gateway)
- **Honest status codes.** All-upstream-throttled → 429 (back off), not 502 (our fault).
- **Timing-safe auth comparison** and routing observability headers (`X-Routed-Via`, `X-Fallback-Attempts`). (free-llm-gateway)
- **Streams held until first token** so pre-first-byte failures stay invisible; mid-stream death must be distinguishable from clean completion. (llm-gateway)

### Hard-won lessons (HN / Reddit / postmortems)
- **GitHub outage postmortem (Aug 2026):** automatic retries turned a blip into a retry storm — auth traffic spiked 10× (7–9k → 70–100k rps). Copilot's VS Code extension kept requesting tokens without pause. Lesson: every retry path needs a budget and a breaker, and token-issuing paths need special protection.
- **HN consensus:** "do something reasonable 90% of the time" is not a production strategy; fail loudly and let someone fix it. Applied here: fail-closed headers, honest 429/504 statuses, no silent degradation.
- **The silent quality collapse (dev.to, Oct 2026):** routers that silently degrade to cheaper lanes destroy trust over ~6 weeks without any dashboard showing it. Applied here: `x-lane` + `x-fallback-attempts` on every response, fail-closed option for sensitive work.
- **Retry at ONE layer only.** n8n's own guidance: if the gateway fails over, clients must NOT also retry — multiplication across layers is the core of the storm. Our runbook must forbid client-side retries (documented in operator-handbook follow-up).
- **arXiv "Retry Amplification in Distributed Systems" (2608.25403):** adaptive retry budgets (tighten when failure rate rises, relax when healthy) beat static caps in deep call graphs. Our per-lane breaker + global admission control is the single-file version of this.

## 2. The brutal critique (what was naive)

**F1. No logical deadline — worst case was a ~280s hang.** 11 lanes × 20s timeouts (plus llm7's 60s) serialized with no overall budget. One slow night = clients hanging for minutes. Industry: one deadline per logical request, period.

**F2. A single revoked API key 401'd the entire router.** 401/403/404 were "returned immediately" as caller errors. But a dead key is lane-scoped, not request-scoped — the request is fine, the lane is broken. One revoked Groq key = total outage despite 10 healthy lanes. This was the single most production-dangerous bug.

**F3. No circuit breaker — just a flat 30s cooldown on every 5xx.** A hard-down lane got re-probed every 30s forever with no escalation, and a blip got punished the same as an outage. No consecutive-failure counting, no backoff escalation (30→60→120→300), no half-open concept. Envoy would laugh.

**F4. All-lanes-throttled returned 502.** When every lane says "slow down," answering 502 ("bad gateway, our fault") is a lie that invites clients to retry — the exact retry-storm trigger. Honest answer: 429 with retry-after.

**F5. No admission control.** One shared ROUTER_KEY + one buggy n8n loop = all lane quotas burned with no backstop. No in-flight cap, no global RPM. The GitHub postmortem is what happens next.

**F6. No hedging — strictly sequential.** Pollinations cold-started at 10.1s in live probing while warm answers take 0.5s. The router would eat the full 10s every cold start instead of firing a parallel attempt. Google's data says hedging after p95 costs ~5% extra for massive tail wins.

**F7. No cache.** Identical prompts (canary checks, heartbeat probes, batch reruns) each burned a lane call. Every serious AI gateway does exact-match caching.

**F8. DoS guard was header-only.** The 1MB cap read `content-length`; a chunked body with no header bypassed it entirely and buffered unbounded into memory.

**F9. Silent mid-stream truncation.** If an SSE stream died mid-flight, the client got a truncated stream indistinguishable from a complete one. No sentinel, no signal.

**F10. Cooldowns with no jitter.** Every isolate's cooldown expired at the same instant → synchronized retry thundering herd on recovery. The AWS "correct the famous post" lesson, ignored.

**F11. Zero routing observability.** Only `x-lane`. No attempt counts, no hedge winner, no breaker state beyond booleans. You can't operate what you can't see.

**F12 (acknowledged, not fixed). Per-isolate state lies under real load.** N isolates × 30 RPM = 30N actual. Documented with a Durable Object upgrade path (needs paid plan — parked). For one operator's traffic this is fine; for anything bigger it's the next audit's problem.

## 3. What changed (all in the single file, zero deps)

1. **Logical deadline** — 90s default, `x-deadline-ms` override (5s–300s clamp). Each attempt gets `min(lane timeout, remaining)`. Expiry → 504 with attempt/failure counts. Worst case went from ~280s to ≤90s.
2. **Lane-scoped 4xx failover** — 401/403/404 now fail over (dead key/dead model); only 400/413/422 return immediately (caller-caused). F2 killed.
3. **Circuit breaker with escalation** — 3 consecutive 5xx/timeout/network failures open the breaker; backoff 30s → 60s → 120s → 300s. Blips (1–2 failures) get NO cooldown: fail fast per request, recover fast. 429s reset the counter (a 429 proves the lane is alive).
4. **Honest 429** — all attempts throttled → 429 + `retry-after` (min remaining cooldown), not 502.
5. **Admission control** — global in-flight cap (50) + global RPM backstop (600), env-tunable (`MAX_INFLIGHT`, `GLOBAL_RPM_LIMIT`). Over → 429 + retry-after. `/health` exempt.
6. **Opt-in hedging** — `x-hedge-after-ms` (1s–30s): after the delay, the next *keyed* lane fires in parallel; first success wins, loser aborted (recorded as `hedged`, not failed, no cooldown). Never crosses into keyless, never streams.
7. **Opt-in exact-match cache** — `x-cache-ttl` (1–300s), cyrb53 key over model+messages+params+failClosed flag, 200-entry cap, non-streaming only. `x-cache: HIT/MISS`.
8. **Real body cap** — byte-stream reader enforces 1MB even for chunked bodies → 413 before buffering.
9. **SSE abort sentinel** — mid-stream death emits `: router upstream aborted` (legal SSE comment, clients ignore it but operators can detect it).
10. **Cooldown jitter** — ±25% on all cooldowns.
11. **Observability** — `x-fallback-attempts` and `x-hedge-winner` on every chat response; `/health` adds `consecFail`, `breakerOpen`, `cooldownSecsRemaining`, `hedged` per lane + router `inflight`/`rpmUsed`.
12. **No same-lane retries** (unchanged, now documented) — failover IS the retry; one client request can never amplify into N calls on one lane. Client-side retries must stay OFF (n8n/GHA).

## 5. Test results: 25/25 green

Harness: `node test-router.mjs` (each scenario in a fresh process). 15 original scenarios kept green (2 updated for honest-429 behavior), 10 new:

- (16) deadline → 504 inside the deadline, 1 attempt, no 220s hang
- (17) groq 401 → mistral serves (dead keys fail over)
- (18) breaker: 3× 500 → open with ~30s backoff, 4th request skips the lane
- (19) admission: 3rd request over GLOBAL_RPM_LIMIT → 429 + retry-after, zero lane calls
- (20) cache: repeat HITs, new prompt MISSes, 2 lane calls for 3 requests
- (21) hedge: hanging lane + 500ms hedge → winner in ~0.5s, loser recorded as hedged (fail=0)
- (22) 2MB chunked body → 413, zero lane calls
- (23) mid-stream death → client sees the abort sentinel
- (24) jitter: retry-after 100 → cooldown in 75–125s
- (25) `x-fallback-attempts` header counts failovers

Two test bugs caught during the run (both in the harness, not the router): a mock SSE stream that enqueue+errored synchronously (Node discards the chunk — mock made pull-based, which is also more faithful), and three scenarios that forgot gemini is lane 1 (made its mock explicit).
